คู่มือนักพัฒนา (Developer Guide)
MAPS 11

เอกสารฉบับนี้จัดทำขึ้นเพื่ออธิบายสถาปัตยกรรมระบบ โครงสร้างโค้ด และหลักการทำงานของแอปพลิเคชัน MAPS 11 (Management of Air Pollution Sector 11) เพื่อให้ทีมนักพัฒนาของ สคพ.11 สามารถนำไปใช้เป็นแนวทางในการบำรุงรักษาและพัฒนาฟีเจอร์เพิ่มเติมในอนาคต

1. สถาปัตยกรรมระบบ (System Architecture)

MAPS 11 เป็นเว็บแอปพลิเคชันประเภท Single Page Application (SPA) ที่ทำงานบนฝั่งไคลเอนต์ (Client-side) เป็นหลัก อาศัยการดึงข้อมูลจาก API ภายนอกมาแสดงผลบนแผนที่ โดยไม่มีระบบฐานข้อมูลในตัว แต่ใช้ Google Apps Script (GAS) เป็นตัวกลางในการดึงข้อมูล

ไลบรารีหลักที่ใช้งาน (Core Dependencies)

  • Leaflet.js ไลบรารีหลักสำหรับสร้างและควบคุมแผนที่แบบ Interactive
  • Leaflet.markercluster สำหรับจัดกลุ่มจุดความร้อนที่อยู่ใกล้กัน (Cluster) เพื่อลดความหนาแน่นบนหน้าจอ
  • Turf.js ไลบรารีสำหรับวิเคราะห์ข้อมูลเชิงพื้นที่ (Spatial Analysis) เช่น การวัดระยะทาง การสร้างกรวยควัน การตรวจสอบจุดในโพลีกอน
  • XLSX.js (SheetJS) สำหรับสร้างและดาวน์โหลดไฟล์ Excel รายงานจุดความร้อน
  • CryptoJS สำหรับเข้ารหัสรหัสผ่านด้วย SHA3 ก่อนอนุญาตให้ดาวน์โหลดข้อมูล

2. โครงสร้างของส่วนแสดงผล (UI Components)

ส่วนต่อประสานกับผู้ใช้เขียนด้วย HTML และ CSS ล้วน โดยแบ่งส่วนประกอบหลักดังนี้

  • Control Panel: แผงควบคุมด้านบน ประกอบด้วยสถานะการโหลดข้อมูล ตัวเลือกช่วงเวลา 24 ชม. หรือ 12 ชม. ช่องค้นหาบ่อขยะ และระบบปักหมุดจุดเกิดเหตุด่วน
  • Loading Overlay: หน้าจอโหลดข้อมูลสีเข้มที่จะแสดงขึ้นมาบังแผนที่ขณะที่ระบบกำลังประมวลผลข้อมูลจาก NASA
  • Map Container: พื้นที่แสดงแผนที่ #map ที่รองรับการคลิกเพื่อดูพิกัด
  • Dynamic Legend: กล่องคำอธิบายสัญลักษณ์มุมซ้ายล่างที่จะปรับเปลี่ยนเนื้อหาอัตโนมัติตามเลเยอร์ที่ผู้ใช้เปิดใช้งาน
  • Toast Container: ระบบแจ้งเตือนมุมขวาบนที่ใช้ฟังก์ชัน showToast() ในการแสดงสถานะต่างๆ

3. การเชื่อมต่อข้อมูล (API Integrations)

ข้อมูล แหล่งที่มา (Source) การนำไปใช้งาน
จุดความร้อน (Hotspots) Google Apps Script (ดึงจาก NASA FIRMS) พล็อตจุดลงบนแผนที่และวิเคราะห์ความเสี่ยงไฟไหม้บ่อขยะ
สถานที่กำจัดขยะ (Landfills) Google Apps Script (จาก Google Sheets) สร้างหมุดรูปถังขยะและวงกลมรัศมีบนแผนที่
ข้อมูลขอบเขตจังหวัด GitHub (ไฟล์ GeoJSON) วาดเส้นขอบเขต 4 จังหวัดและใช้กรองข้อมูลจุดความร้อน
แปลงพิกัดเป็นที่อยู่ (Reverse Geocoding) Longdo Map API ค้นหาตำบล อำเภอ จังหวัด จากพิกัด Lat/Lon
ข้อมูลสภาพอากาศ (Wind Data) Open-Meteo API ดึงความเร็วและทิศทางลมเพื่อจำลองทิศทางควันไฟ

4. คำอธิบายฟังก์ชันหลัก (Core Functions)

4.1. การประมวลผลจุดความร้อน (Hotspot Processing)

ฟังก์ชัน fetchNasaData() ทำหน้าที่ดึงข้อมูลจาก GAS ระบบจะใช้วิธีแบ่งการประมวลผลเป็นชุดย่อย (Chunk Processing) ผ่าน setTimeout เพื่อป้องกันไม่ให้เบราว์เซอร์ค้างหากมีจุดความร้อนจำนวนมาก

function processHotspotChunk() {
    let end = Math.min(i + chunkSize, data.points.length);
    for (; i < end; i++) {
        // ...ประมวลผลพิกัด แปลงเวลา
        // ใช้ Turf.js ตรวจสอบว่าพิกัดอยู่ในโพลีกอน 4 จังหวัดหรือไม่
        if (turf.booleanPointInPolygon(turfPt, b)) {
            // ...เก็บข้อมูลเข้า globalCoreFeatures
        }
    }
    // ...ถ้ายังไม่หมดให้เรียกตัวเองใหม่
}

4.2. การวิเคราะห์ความเสี่ยงไฟไหม้บ่อขยะ (Risk Analysis)

ฟังก์ชัน calculateWasteFireRisk() จะทำงานทุกครั้งที่มีการอัปเดตจุดความร้อน ระบบจะใช้ Turf.js วัดระยะทางระหว่างจุดความร้อนทุกจุดกับบ่อขยะทุกแห่ง หากมีระยะห่างน้อยกว่าหรือเท่ากับ RISK_RADIUS_KM (0.5 กม.) ระบบจะสร้างวงกลมแจ้งเตือนสีแดงกระพริบรอบบ่อขยะนั้น

let distance = turf.distance(sitePt, hotPt, {units: 'kilometers'});
if (distance <= RISK_RADIUS_KM) {
    nearHotspots++;
    // ตรวจพบความเสี่ยง
}

4.3. การจำลองทิศทางควันไฟ (Plume Modeling)

เมื่อมีการปักหมุดจุดเกิดเหตุ ฟังก์ชัน drawPlumeAndCalculateRisk() จะดึงข้อมูลลมจาก Open-Meteo มาคำนวณทิศทางที่ควันจะลอยไป โดยบวกเพิ่ม 180 องศาจากทิศที่ลมพัดมา จากนั้นใช้ Turf.js คำนวณจุดปลายทาง (Destination) เพื่อสร้างรูปโพลีกอนกรวยควันระยะ 5 กิโลเมตร มุมกระจาย 40 องศา

const smokeAngle = (dir + 180) % 360; // ทิศที่ควันลอยไป
const leftPt = turf.destination([lon, lat], distance, leftBearing, {units: 'kilometers'});
const rightPt = turf.destination([lon, lat], distance, rightBearing, {units: 'kilometers'});
// นำจุดที่ได้ไปวาด L.polygon()

4.4. การป้องกันข้อมูลและ Export Excel

ก่อนดาวน์โหลดไฟล์ ระบบจะบังคับให้กรอกรหัสผ่าน รหัสผ่านที่รับมาจะถูกนำไปแฮชด้วย SHA3 ผ่านไลบรารี CryptoJS จากนั้นนำไปเทียบกับค่า Hash ที่ฝังไว้ในโค้ด (Hardcoded Hash) หากตรงกันจึงจะสร้างไฟล์ Excel ด้วย SheetJS

const userHash = CryptoJS.SHA3(cleanPassword, { outputLength: 512 }).toString();
if (userHash !== TARGET_HASH) {
    showToast("รหัสผ่านไม่ถูกต้อง", "error");
    return;
}

5. ข้อควรระวังและข้อจำกัด (Limitations & Considerations)

  • Longdo API Key: คีย์ที่ฝังอยู่ในโค้ด bce812933744d2530d26f0fabb0017cf มีข้อจำกัดโควตาการเรียกใช้งานต่อวัน หากนำไปใช้งานหนักควรจดทะเบียน API Key ใหม่สำหรับหน่วยงาน
  • ความเร็วลม: Open-Meteo อัปเดตข้อมูลทุกๆ ชั่วโมง อาจไม่ตรงกับสภาพลมจริง ณ วินาทีนั้นแบบเป๊ะๆ จึงมีฟังก์ชัน ปรับทิศ ให้เจ้าหน้าที่แก้ไของศาลมได้เองหน้างาน
  • ความปลอดภัยรหัสผ่าน: การแฮชรหัสผ่านฝั่งไคลเอนต์เป็นเพียงการป้องกันระดับเบื้องต้น ผู้ที่มีความรู้ด้านโปรแกรมมิ่งสามารถแก้ไขโค้ดผ่าน Developer Tools เพื่อข้ามการตรวจสอบนี้ได้ หากข้อมูลมีความลับสูงมากควรย้ายการตรวจสอบรหัสผ่านไปไว้ที่ฝั่งเซิร์ฟเวอร์ (GAS)
